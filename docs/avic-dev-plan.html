SECTION 01

Executive Summary

ℹ️
The AVIC Portal is a multi-role web application that automates the full insurance claim lifecycle — from first notice of loss through document verification, adjuster review, garage estimate reconciliation, and final payout. Built entirely with vanilla PHP, HTML, JS, and MariaDB, it mimics the separation of concerns, routing, and middleware patterns that frameworks like Laravel provide, but through hand-crafted, teachable code.

🎯 Primary Goal

Digitise and streamline the insurance claim lifecycle, reducing manual paperwork, decision delays, and payout errors through a structured, role-based web portal.

📚 Academic Scope

Demonstrate full-stack proficiency in PHP (OOP/PDO), relational schema design, vanilla JS DOM manipulation, file handling, session security, and deployment without framework scaffolding.

SECTION 03

System Architecture

🔷
The architecture follows a custom MVC-inspired pattern: all HTTP requests enter through public/index.php, pass through the Router → Middleware → Controller → Model chain, and the controller renders a view via PHP output buffering into a base layout. This exactly mirrors Laravel's request lifecycle without any framework dependency.

Request Flow

  • Browser → .htaccess rewrites to public/index.php
  • Router matches URI pattern to controller/method
  • Auth middleware checks session and role
  • CSRF middleware validates token on POST
  • Controller calls Model(s), fetches data via PDO
  • View file rendered into base layout
  • Response sent to browser

PHP Architecture Pattern

  • Core/ — Router, Session, Auth, CSRF, Validator, FileUploader, Mailer
  • Models/ — One class per DB entity, extends BaseModel with PDO query builder
  • Controllers/ — Handle request → response, thin logic
  • Views/ — Pure PHP templates with layouts/partials
  • Middleware/ — Auth, Role, CSRF guards (called by Router)

Uploads Architecture (Security-Critical)

The uploads/ directory sits outside the public/ web root. Files are served via a PHP proxy script (public/file.php?id=X&token=Y) that checks authentication and file ownership before streaming the binary. This prevents direct URL access to sensitive documents (police reports, medical records).

MariaDB Schema

✅
All tables use InnoDB engine (transactions, FK constraints), utf8mb4 charset (emoji + Unicode safe), and strategic indexes on every foreign key and high-cardinality filter column (email, status, claim_number, session_token).

CREATE DATABASE IF NOT EXISTS avic_portal
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE avic_portal;

-- 1. USERS (all roles share one table)
CREATE TABLE users (
    id           INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    full_name    VARCHAR(100) NOT NULL,
    email        VARCHAR(150) NOT NULL UNIQUE,
    phone        VARCHAR(20),
    password     VARCHAR(255) NOT NULL,              -- bcrypt
    role         ENUM('claimant','adjuster','admin','garage') DEFAULT 'claimant',
    status       ENUM('active','suspended','pending') DEFAULT 'pending',
    avatar       VARCHAR(255),
    email_verified_at TIMESTAMP NULL,
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    last_login   TIMESTAMP NULL,
    INDEX idx_role (role), INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 2. POLICIES
CREATE TABLE policies (
    id             INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id        INT UNSIGNED NOT NULL,
    policy_number  VARCHAR(50) NOT NULL UNIQUE,
    vehicle_make   VARCHAR(60),
    vehicle_model  VARCHAR(60),
    vehicle_year   YEAR,
    vehicle_vin    VARCHAR(17) UNIQUE,

    end_date       DATE NOT NULL,
    status         ENUM('active','expired','cancelled') DEFAULT 'active',
    created_at     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,

Features & Functionalities

🔐 Authentication Module

  • Registration with email verification (token link via PHPMailer)
  • Login with bcrypt password verification and session regeneration
  • Forgot/reset password (timed 1-hour tokens in password_resets table)
  • Remember-me (persistent cookie + server-side token)
  • Forced logout on role change or account suspension

📝 Claim Filing — Multi-Step Wizard

  • Step 1 — Policy: Enter or select policy number; auto-populates vehicle details; validates policy is active and not expired.
  • Step 2 — Incident: Date, location (manual + optional map pin), claim type selector, free-text description.
  • Step 3 — Documents: Drag-and-drop multi-file uploader for accident photos, police report PDF. Shows preview thumbnails. Max 10 MB per file.
  • Step 4 — Estimate: Garage name/phone/address, parts + labour breakdown, total estimate, optional estimate PDF upload.
  • Step 5 — Review & Submit: Summary of all entered data before final submission. "Save as Draft" option persists data without submitting.

🔍 Adjuster Review Panel

  • Queue of all submitted / under_review claims with SLA countdown timer
  • Side-by-side: claim details left, document viewer right (in-browser PDF/image display)
  • Action buttons: Approve, Reject, Request More Documents, Escalate to Admin
  • Set approved payout amount (may differ from estimate); write decision notes
  • Mark individual documents as verified/unverified with notes

💰 Payout Processing

  • Admin initiates payout for approved claims
  • Payment method selection: bank transfer, cheque, mobile money
  • Auto-generated reference number (PAY-YYYYMMDD-XXXXX)
  • Status lifecycle: pending → processing → completed / failed
  • Downloadable payout receipt PDF (mPDF) sent to claimant email

🔔 Notifications System

  • DB-backed notifications per user (bell icon + dropdown)
  • JS polling every 30s for unread count (no WebSocket needed)
  • Transactional emails on: claim submitted, status changed, doc verified, payout processed
  • In-app flash messages for immediate actions

📊 Admin Dashboard

  • KPI cards: open claims, avg resolution days, total payouts this month
  • Claims by status (simple bar chart via vanilla JS canvas)
  • User management (approve pending, suspend, change role)
  • Exportable reports as CSV / PDF

🗂️ Document Management

  • Secure file proxy — no direct URLs to uploads/
  • Type enforcement: photos → JPEG/PNG/WEBP; reports → PDF only
  • Duplicate detection by file hash (MD5 stored in DB)
  • In-browser preview: <img> for photos, <iframe> or PDF.js for PDFs
  • Adjuster doc verification with timestamp + name

📈 Status Tracking Timeline

  • Claimant-visible history from claim_status_history
  • Visual step-bar (Draft → Submitted → Under Review → Approved → Paid)
  • Timestamps at each transition
  • Notes/reason visible when status is "rejected" or "pending_docs"

Core Code Patterns

PHPcore/Router.php
class Router {
    private static $routes = [];

    public static function add($method, $pattern, $handler, $middleware = []) {
        self::$routes[] = compact('method', 'pattern', 'handler', 'middleware');
    }
    public static function get($p, $h, $m = [])  { self::add('GET', $p, $h, $m); }
    public static function post($p, $h, $m = []) { self::add('POST', $p, $h, $m); }

    public static function dispatch() {
        $uri    = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
        $method = $_SERVER['REQUEST_METHOD'];

        foreach (self::$routes as $route) {
            $regex = '#^' . preg_replace('#\{(\w+)\}#', '([^/]+)', $route['pattern']) . '$#';
            if ($route['method'] === $method && preg_match($regex, $uri, $matches)) {
                array_shift($matches); // drop full match
                foreach ($route['middleware'] as $mw)
                    (new $mw)->handle();
                [$class, $action] = explode('@', $route['handler']);
                (new $class)->$action(...$matches);
                return;
            }
        }
        http_response_code(404); include view_path('errors/404');
    }
}
PHPcore/Model.php — Base QueryBuilder
class Model {
    protected static $table;
    protected static function db(): PDO {
        return Database::getInstance();
    }
    public static function find($id): ?array {
        $stmt = self::db()->prepare(
            "SELECT * FROM " . static::$table . " WHERE id = ? LIMIT 1"
        );
        $stmt->execute([$id]);
        return $stmt->fetch(PDO::FETCH_ASSOC) ?: null;
    }
    public static function where($col, $val): array {
        $stmt = self::db()->prepare(
            "SELECT * FROM " . static::$table . " WHERE {$col} = ?"
        );
        $stmt->execute([$val]);
        return $stmt->fetchAll(PDO::FETCH_ASSOC);
    }
    public static function create(array $data): int {
        $cols = implode(',', array_keys($data));
        $phs  = implode(',', array_fill(0, count($data), '?'));
        $stmt = self::db()->prepare(
            "INSERT INTO " . static::$table . " ({$cols}) VALUES ({$phs})"
        );
        $stmt->execute(array_values($data));
        return (int) self::db()->lastInsertId();
    }
    public static function update($id, array $data): bool {
        $set  = implode(',', array_map(fn($k) => "{$k}=?", array_keys($data)));
        $stmt = self::db()->prepare(
            "UPDATE " . static::$table . " SET {$set} WHERE id=?"
        );
        return $stmt->execute([...array_values($data), $id]);
    }
}
PHPcore/FileUploader.php
class FileUploader {
    private const ALLOWED = [
        'accident_photo'  => ['image/jpeg','image/png','image/webp'],
        'police_report'   => ['application/pdf'],
        'repair_estimate' => ['application/pdf','image/jpeg'],
    ];

    public function handle(array $file, string $docType): array {
        if ($file['error'] !== UPLOAD_ERR_OK)
            throw new RuntimeException('Upload error code: ' . $file['error']);

        // 1. Size check
        $maxBytes = (int) setting('max_upload_mb') * 1024 * 1024;
        if ($file['size'] > $maxBytes)
            throw new RuntimeException('File exceeds size limit');

        // 2. MIME check (from actual bytes, not extension)
        $finfo    = new finfo(FILEINFO_MIME_TYPE);
        $realMime = $finfo->file($file['tmp_name']);
        if (!in_array($realMime, self::ALLOWED[$docType] ?? []))
            throw new RuntimeException('Invalid file type for ' . $docType);

        // 3. Generate safe unique filename
        $ext        = pathinfo($file['name'], PATHINFO_EXTENSION);
        $storedName = bin2hex(random_bytes(16)) . '.' . strtolower($ext);
        $destDir    = UPLOAD_ROOT . '/' . $docType . 's/';
        $destPath   = $destDir . $storedName;

        if (!is_dir($destDir)) mkdir($destDir, 0750, true);
        move_uploaded_file($file['tmp_name'], $destPath);

        return [
            'stored_name'   => $storedName,
            'file_path'     => $destPath,
            'original_name' => htmlspecialchars($file['name']),
            'file_size'     => $file['size'],
            'mime_type'     => $realMime,
        ];
    }
}
JavaScriptassets/js/claim-wizard.js — Multi-Step Logic
const wizard = {
  currentStep: 1,
  totalSteps:  5,

  init() {
    this.renderStep(this.currentStep);
    this.restoreDraft();
    setInterval(() => this.saveDraft(), 60000);
  },

  renderStep(n) {
    document.querySelectorAll('.wizard-step').forEach((el, i) => {
      el.classList.toggle('active', i + 1 === n);
    });
    document.querySelectorAll('.step-indicator li').forEach((li, i) => {
      li.classList.toggle('done',    i + 1 < n);
      li.classList.toggle('current', i + 1 === n);
    });
  },

  next() {
    if (!this.validateStep(this.currentStep)) return;
    this.currentStep = Math.min(this.currentStep + 1, this.totalSteps);
    this.renderStep(this.currentStep);
    window.scrollTo(0, 0);
  },

  validateStep(n) {
    const step = document.querySelector(`.wizard-step[data-step="${n}"]`);
    const required = [...step.querySelectorAll('[required]')];
    let valid = true;
    required.forEach(f => {
      const err = f.nextElementSibling;
      if (!f.value.trim()) {
        f.classList.add('invalid');
        if (err?.classList.contains('field-error')) err.hidden = false;
        valid = false;
      } else {
        f.classList.remove('invalid');
        if (err?.classList.contains('field-error')) err.hidden = true;
      }
    });
    return valid;
  },

  saveDraft() {
    const data = {};
    document.querySelectorAll('#claim-form [name]').forEach(f => data[f.name] = f.value);
    sessionStorage.setItem('claim_draft', JSON.stringify(data));
  },

  restoreDraft() {
    const saved = JSON.parse(sessionStorage.getItem('claim_draft') || 'null');
    if (!saved) return;
    Object.entries(saved).forEach(([k, v]) => {
      const f = document.querySelector(`[name="${k}"]`);
      if (f) f.value = v;
    });
  }
};

document.addEventListener('DOMContentLoaded', () => wizard.init());

const NotifyPoll = {

    this.poll();
    setInterval(() => this.poll(), this.interval);
  },
  async poll() {
    try {
      const res  = await fetch('/api/notifications', { credentials: 'same-origin' });
      const data = await res.json();
      const badge = document.getElementById('notif-badge');
      if (badge) badge.textContent = data.unread_count || '';
      badge?.classList.toggle('hidden', !data.unread_count);
      this.renderDropdown(data.items);

      <a href="/claims/${n.claim_id}" class="notif-item ${n.is_read ? '' : 'unread'}">
        <strong>${n.title}</strong><span>${n.message}</span>
      </a>`).join('');
  }
};

SECTION 10

Security Implementation

⚠️
Security is non-negotiable even in a class project. An insurance portal handles PII, financial amounts, and legal documents. These controls must be implemented from day one, not retrofitted.

🛡️ Input & Injection

  • All DB queries via PDO prepared statements — never string-interpolated
  • Output escaped with htmlspecialchars() in every view
  • Server-side validation before any DB write (Validator class)
  • Strip/encode HTML from rich-text fields
  • Integer/type casting on all numeric inputs

🗝️ CSRF Protection

  • 64-byte random token generated per session
  • Hidden <input name="_csrf_token"> in every form
  • AJAX calls send it as X-CSRF-Token header
  • CsrfMiddleware validates on every POST/PUT/DELETE
  • Rotate token on login/logout/privilege change

📁 File Upload Security

  • MIME validated from file bytes (finfo), not extension or Content-Type header
  • Filenames replaced with UUID-based names — no original name on disk
  • Uploads directory outside web root (unreachable by URL)
  • Files served only via PHP proxy that checks auth + ownership
  • Max file size enforced server-side (PHP ini + app check)

🔐 Session & Auth

  • Passwords hashed with password_hash(PASSWORD_BCRYPT)
  • Session regenerated on login (session_regenerate_id(true))
  • Session cookie: HttpOnly, Secure, SameSite=Strict
  • Idle timeout: destroy session after 30 min inactivity
  • Rate-limit login attempts (5/min per IP via DB counter)

⚡ Additional Controls

  • IDOR prevention: Every resource query includes WHERE id = ? AND user_id = ? for non-admin roles — no sequential ID guessing
  • Error handling: Generic errors shown to users; detailed errors logged to logs/error.log only
  • Environment separation: DB credentials, mail passwords, and secret keys live in .env (never committed to version control — add to .gitignore)

Improvements & Enhancements

UX/DESIGN
Progressive Claim Wizard with Auto-Save Indicator

Show a "Saved" badge with timestamp after each auto-save tick. Allow claimants to return and resume an in-progress draft from a "Continue Draft" link on their dashboard. This reduces drop-off on long forms.

FEATURE
OCR for Scanned Police Reports

Integrate Tesseract OCR via PHP exec() or an external API (OCR.space free tier) to extract text from uploaded police report PDFs. Populate the police report reference number field automatically and flag discrepancies with what the user entered.

SECURITY
Two-Factor Authentication (TOTP)

For adjuster and admin accounts, require TOTP (Google Authenticator compatible) using a library like RobThree/TwoFactorAuth. This protects high-privilege accounts without adding cost.

INTEGRATION
SMS Notifications via Africa's Talking

Africa's Talking provides a free sandbox SMS API — ideal for Uganda/East Africa. Send SMS alerts on claim submission confirmation and payout processing. More reliable than email for claimants with intermittent internet.

PERFORMANCE
Output Caching for Read-Heavy Pages

Cache admin dashboard statistics (total claims, avg resolution time) in the settings table with a last-computed timestamp. Regenerate only every 10 minutes. Eliminates expensive COUNT/AVG aggregation queries on every dashboard load.

DATA
VIN Lookup API Integration

When a policy is created or a claim is filed, call the free NHTSA VIN API (api.nhtsa.dot.gov) to auto-populate and verify vehicle make, model, and year from the VIN. Prevents data entry errors and potential fraud.

FEATURE
Adjuster Workload Balancing

When a claim is submitted, auto-assign it to the adjuster with the fewest open claims. Store adjuster capacity (max concurrent claims) in user metadata. Prevents queue pile-up and makes SLA tracking meaningful.

COMPLIANCE
Data Retention & GDPR/Privacy Controls

Add a scheduled PHP script (run via a cron-like mechanism: a URL-triggered endpoint with a secret key, since free hosts don't support cron jobs) to anonymise resolved claims older than 5 years. Add user data-deletion request handling.

SECTION 15

Missed Aspects & Critical Gaps

🚨
These are areas commonly overlooked in class projects of this type. Each one will be asked about in a viva/presentation or is needed for the system to be realistic and defensible.

❌ Missing: Policy Validation at Claim Filing

The system must verify that (a) the policy is active and not expired at the incident date, (b) the claim type is covered under that policy's coverage tier, and (c) no prior claim for the same incident already exists. Without this, fraudulent duplicate claims are trivially possible.

❌ Missing: Coverage Limit Enforcement

The adjuster-set approved amount must be capped at the policy's coverage_limit minus any amount already paid on prior claims for the same policy period. Add this as a server-side check in AdjusterController before saving the approved amount.

⚠️ Missing: SLA Enforcement & Escalation

The 14-day claim resolution SLA defined in settings has no mechanism to surface breaches. Add a due_date field on claims, highlight overdue claims in red on the adjuster queue, and notify admin when SLA is breached. Use a pseudo-cron via PHP to check this.

⚠️ Missing: Third-Party Vehicle Counter-Party

In a real collision, there's often a third party whose vehicle is also damaged. The schema has no concept of the counter-party vehicle, owner, or their policy. This matters for liability claims. Add a third_party_details JSON column to claims for MVP.

📌 Missing: Printable / PDF Claim Summary

Claimants and adjusters need a printable, official-looking summary of the claim with all attached documents referenced. Use mPDF to generate a structured PDF from a PHP view on demand. Essential for the "payout receipt" and "claim acknowledgement" documents.

📌 Missing: Garage Portal Onboarding

The Garage role is defined in the schema but its onboarding flow (how garages register, how adjusters assign a claim to a specific garage, how the garage receives the work order) is not described. Define this flow explicitly: Admin approves garage accounts, adjuster selects a registered garage from a list, garage receives email with claim ID and link to their portal.

💡 Consider: Webhook / Event System

As claims move through statuses, multiple side-effects trigger (notifications, emails). Rather than calling these inline in every controller, create a simple EventDispatcher class with listeners. Makes the codebase much cleaner and testable — directly mirrors Laravel Events without the magic.

💡 Consider: Admin Impersonation for Support

Allow admin to "view as" any claimant — a one-click login impersonation stored in session. Essential for support and demos. Exit impersonation returns to admin session cleanly. Laravel Telescope provides this; build a 20-line PHP equivalent.

🎓
Academic presentation tip: Your examiner will almost certainly ask "How does your system prevent duplicate claims for the same incident?", "What happens if the payout exceeds the policy limit?", and "How are uploaded files secured from direct access?" Make sure you can answer all three from the implementation, not just from this plan.
